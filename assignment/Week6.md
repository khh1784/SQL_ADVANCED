# 1️⃣ 학습 내용 정리

## 1. 스토어드 프로시저 사용 방법 

<!-- 스토어드 프로시저에 관해 배우게 된 점을 적어주세요. -->
```
- 스토어드 프로시저 (Stored Procedure): 여러 개의 SQL 문을 하나로 묶어 모듈화한 데이터베이스 개체로, 복잡한 쿼리를 간편하게 재호출하고 처리 속도를 향상시킬 수 있음
- 기본 구조 및 호출: DELIMITER $$ ~ END $$로 구분을 지어 생성하며, 실행할 때는 CALL 프로시저이름()을 사용
- 매개변수 활용:
  1. IN (입력 매개변수): 프로시저 호출 시 외부에서 값을 전달받음 (예: IN txtName VARCHAR(10))
  2. OUT (출력 매개변수): 프로시저 내부 실행 결과 값을 호출한 쪽에 돌려줌 (예: OUT userCount INT)
- 동적 SQL: PREPARE 문으로 SQL 문장을 미리 준비해 두고, EXECUTE 문으로 변수 값을 전달하여 가변적인 쿼리를 동적으로 실행할 수 있음
```

## 2. 스토어드 함수와 커서 

<!-- 스토어드 함수와 커서에 관해 배우게 된 점을 적어주세요. -->
```
- 스토어드 함수 (Stored Function): 사용자가 직접 정의하여 SELECT 문 안에서 호출해 사용하는 함수로, 단일 값을 계산하여 반환(RETURN)할 때 사용
  cf) 프로시저와의 차이: RETURNS 절로 반환 형식을 지정하고 RETURN 문으로 값을 반환하며, 입력 매개변수만 사용할 수 있으며(IN 키워드                           생략), CALL이 아닌 SELECT 문 내에서 사용됨
      생성 전 SET GLOBAL log_bin_trust_function_creators = 1; 구문으로 함수 생성 권한을 허용해야 함
- 커서 (Cursor): 테이블의 행(Row)을 한 줄씩 차례대로 넘어가면서 세밀하게 처리하기 위한 데이터 구조
- 커서의 5단계 처리 절차:
  1. 커서 선언 (DECLARE 커서이름 CURSOR FOR SELECT ...)
  2. 커서 열기 (OPEN 커서이름)
  3. 데이터 가져오기 및 반복 (FETCH 커서이름 INTO 변수들 + WHILE 반복문)
  4. 루프 종료 조건 처리 (DECLARE CONTINUE HANDLER FOR NOT FOUND)
  5. 커서 닫기 (CLOSE 커서이름)
```

## 3. 자동 실행되는 트리거 

<!-- 트리거에 관해 배우게 된 점을 적어주세요. -->
```
- 트리거 (Trigger): 테이블에 INSERT, UPDATE, DELETE 등의 데이터 변경 이벤트(DML)가 발생할 때 자동으로 호출되어 실행되는 스토어드 프                     로그램
  -> 주요 용도: 데이터 무결성 검증, 데이터 삭제/수정 시 이력(Audit) 자동 기록 및 백업 테이블 관리
- 임시 테이블 (OLD & NEW):
  NEW 테이블: INSERT나 UPDATE 작업 시 새로 들어오는 데이터가 임시로 저장되는 공간
  OLD 테이블: DELETE나 UPDATE 작업 시 기존에 존재하던(수정/삭제 전) 데이터가 임시로 저장되는 공간
```
